# 内置篇目补全规范（全文 + 逐词注释）

## 目标

把 `app/assets/content/lessons/*.json` 中的指定篇目，从“3–4 句样例”替换为**教材完整课文**（文言文按句切分），并逐句给出译文与逐词注释。

## 文件格式（严格）

```json
{
  "id": "shishuo",
  "title": "师说",
  "author": "韩愈",
  "source": "《昌黎先生集》",
  "volume": "必修上册",
  "tags": ["课标", "议论"],
  "reviewed": true,
  "summary": "……",
  "sentences": [
    {
      "id": "shishuo-001",
      "order": 1,
      "text": "古之学者必有师。",
      "translation": "古代求学的人一定有老师。",
      "tokens": [
        {"surface": "学者", "pos": "名词", "gloss": "求学的人"},
        {"surface": "师", "pos": "名词", "gloss": "老师"}
      ]
    }
  ]
}
```

## 硬性规则（会被校验脚本检查）

1. 每个 sentence 必须有 `text`、`translation`、`tokens`。
2. `sentence.id` 格式 `<lessonId>-NNN`，从 001 开始，按课文顺序递增；`order` 从 1 递增。
3. `tokens[].surface` 必须是**该句原文中连续出现的文字**，且**按在句中出现的先后顺序**排列。
   - 同一个字在句中多次出现时，按出现顺序列；如果会混淆，改用更长的词组作为 surface（例如“青于蓝”）。
4. `tokens` 要**逐词详细**：每句一般 2–8 个，重点是实词、虚词、活用、古今异义、特殊句式标志；不要只标 1 个。
5. `gloss` 必须给“在句中”的释义，简洁（不超过 30 字）；`pos` 填词性（名词/动词/形容词/副词/介词/连词/助词/代词/兼词/固定结构等）。
6. 保留原文件的 `id/title/author/source/volume/tags`；`reviewed` 用 `true`；`summary` 可更新。
7. 长文（《滕王阁序》《鸿门宴》）必须覆盖教材所选全部段落，不得只写开头几句；全文按句切分，句子数量以教材为准。
8. 只允许修改分配给自己的 lesson 文件，**不要改** `index.json`、其他篇目、代码。

## 校验方法

```powershell
$py = "C:\Users\lxlra\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
& $py "D:\学习\DScoding项目测试\wenyan\tools\validate_content.py"
```

校验会检查：字段、id/order、token 是否能在 text 中按顺序找到、译文/释义非空。出现 `找不到 token` 就调整 token 顺序或改用不会歧义的 surface。

## 写入方式（避免 BOM）

用 Python 写 JSON：

```python
import json, io
with io.open(path, "w", encoding="utf-8", newline="\n") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```
